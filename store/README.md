## Step 1: confirm the package

```bash
# Rebuild after any source change (version bumps come from manifest.json)
zip -r -X store/wescreen-$(node -p "require('./manifest.json').version").zip \
  manifest.json background.js recorder.html recorder.js recorder.css \
  popup.html popup.js popup.css icons _locales -x '*.DS_Store'
```

Confirm `manifest.json` inside the zip has `"default_locale": "en"` and that `_locales/` contains
both `en` and `zh_CN`. Partner Center only lists a language when the locale folder is present.

## Step 4: privacy — exact answers

**Single purpose description**

> WeScreen records the screen, a window, or a browser tab to a local WebM video file, and provides
> controls for that recording (countdown, pause/resume, audio mixing, and quality settings). It has
> no other purpose and no server-side component.

**Permission justification**

| Permission | Justification to paste |
| --- | --- |
| `storage` | Saves the user's recording preferences (resolution, frame rate, quality, countdown, language, audio toggles) and buffers recording chunks locally in IndexedDB so an interrupted recording can be recovered. Nothing is transmitted. |
| `downloads` | Saves the finished WebM recording to the user's Downloads folder, which is the only way the extension delivers its output. |

**Are you using remote code?** → **No.** The extension bundles all of its code; it makes no network
requests and loads nothing remotely.

**Data usage — what to declare.** WeScreen collects nothing, so select **no** data categories.
Be accurate rather than cautious here: declaring collection that does not happen would contradict
the privacy policy, which states plainly that no data is collected or transmitted.

**I certify that the following disclosures are true** — check every box. The extension genuinely
meets these: it does not sell or transfer data (it has none), does not use data for purposes
unrelated to its single purpose, and does not use data to determine creditworthiness or for lending.

**Privacy policy URL** → the Pages URL from step 0.

## Step 6: submit

1. Paste the **Notes for certification** block from `store/listing.md`.
2. **Publish.** Certification takes up to 7 business days.
3. After approval the status becomes **In the Store**.

## Tracking an update

Bump `version` in `manifest.json`, regenerate the zip, and re-upload. Partner Center requires a
higher version than the published one. Note in the certification notes what changed — the
`CHANGELOG.md` entry is written for exactly that purpose.

## Regenerating the graphics

```bash
python3 scripts/build-store-assets.py
```

Requires Pillow. The script reads `assets/logo.png` and `assets/screenshot-*.png`, so re-capture
those first if the UI changed, then rerun it. It prints the size of every asset it writes and the
required size next to it.
