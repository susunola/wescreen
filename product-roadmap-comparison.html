Decision memo · 27 September 2026

Build the trusted local recorder.

Do not chase Loom’s cloud collaboration suite first. Win the Edge niche with fast, transparent local capture, then add tutorial-making features where they improve the exported file.

Recommendation

Position WeScreen as “the local-first Edge screen recorder”: no account, no upload, no tracking, explicit capture consent. The next differentiator is a frictionless link-assisted tab-recording flow, not silent recording or hosted sharing.

Why now

WeScreen already owns the foundational capabilities: local output, audio mix, recovery chunks, preview, quality controls, and privacy documentation. Competitors are broad video suites; their breadth creates an opening for a focused, trustworthy utility.

Competitive read

Loom: collaboration benchmark

Its advantage is instant cloud sharing, editing, comments and captions. Competing feature-for-feature requires hosting, privacy controls, support, and a collaboration product—not merely a recorder.

Screenity: closest product reference

Screenity pairs a privacy-friendly extension with camera, annotation, click focus and an editor. It is the right reference for improving output quality without abandoning local-first principles.

ScreenPal: creation suite benchmark

Its breadth—camera layouts, drawing, trimming, captions and hosted content—shows the expected tutorial-creation stack, but not the first release scope.

Hard product boundary

“Paste a URL and silently record it” is not an acceptable promise. Chromium’s tab-capture API requires user invocation and capture of an active, permitted tab.

Ship instead: paste link → open target tab → a clear one-click “record this tab” confirmation → recording continues while the user changes tabs.

This is both compliant and easy to explain in the UI.

Execution sequence

Roadmap that compounds

v0.2 · NOW

Make local recording unbreakable

  • Polish status/badge, storage warning, recovery UX and complete English/Chinese UI.
  • Test screen/window/tab, multi-display, audio permissions, long recordings and cancellation states.
  • Outcome: users trust the tool for a long recording.
v0.3 · NEXT

Link-assisted tab recording

  • URL field, recent links, duration presets and “open target” workflow.
  • One explicit capture confirmation on the target tab; locally stored optional schedules only.
  • Outcome: record recurring dashboards, demos and web flows with minimal friction.
v0.4 · LATER

Make recordings teachable

  • Camera PiP, cursor/click indicators, capture-area selection and annotations.
  • Post-record trim/re-export. Validate in-browser encoding before promising MP4/GIF.
  • Outcome: tutorial-quality output without a cloud dependency.
v1.0 · RELEASE

Publish with a clear trust story

  • Microsoft Edge Add-ons listing, icon set, screenshots, privacy policy and accurate permission copy.
  • Outcome: a store-ready utility with a memorable local-only promise.

What not to build yet

Cloud uploads, viewer analytics, team libraries, AI summaries and collaboration comments all multiply operating, privacy and support burden. Only introduce them as optional integrations after the local recorder is dependable and the tutorial-output features are proven.
